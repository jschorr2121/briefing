# Briefing Mobile App Setup Guide

## Architecture

Briefing uses **Capacitor** to wrap the Next.js web app in a native iOS/Android shell.

- **Web app**: Hosted on Vercel (`briefing-five.vercel.app`)
- **Mobile app**: Native shell loads the Vercel URL in a WebView
- **Native features**: Splash screen, status bar, push notifications, haptics
- **Updates**: Use Capgo for live OTA updates (no App Store review for web code changes)

## Prerequisites

### For iOS Development
- **Mac with Xcode 15+** (required — cannot build iOS on Windows/Linux)
- **Apple Developer Account** ($99/year) — [developer.apple.com](https://developer.apple.com)
- **CocoaPods**: `sudo gem install cocoapods`

### For Android Development
- **Android Studio** — [developer.android.com/studio](https://developer.android.com/studio)
- **Google Play Developer Account** ($25 one-time) — [play.google.com/console](https://play.google.com/console)

## Quick Start

### 1. Install Dependencies
```bash
npm install
```

### 2. Sync Native Projects
```bash
npx cap sync
```

### 3. Open in IDE
```bash
# iOS (requires Mac)
npx cap open ios

# Android
npx cap open android
```

### 4. Run on Device/Simulator
- **iOS**: Select a simulator or connected device in Xcode, press ▶️
- **Android**: Select a device/emulator in Android Studio, press ▶️

## iOS App Store Submission

### First-Time Setup
1. Log into [App Store Connect](https://appstoreconnect.apple.com)
2. Create a new app:
   - **Bundle ID**: `com.briefing.news`
   - **Name**: Briefing
   - **Primary Language**: English
   - **SKU**: `briefing-001`

### Required Assets
- **App Icon**: 1024x1024 (already generated in `resources/ios/icon-1024.png`)
- **Screenshots**: Required for each device size
  - iPhone 6.7" (1290x2796) — iPhone 15 Pro Max
  - iPhone 6.5" (1284x2778) — iPhone 15 Plus
  - iPad Pro 12.9" (2048x2732) — if supporting iPad
- **App Description**: Max 4000 chars
- **Privacy Policy URL**: Required (host on Vercel or GitHub Pages)
- **Support URL**: Required

### Build & Upload
1. In Xcode: **Product → Archive**
2. **Distribute App → App Store Connect → Upload**
3. In App Store Connect: select the build, fill in metadata, submit for review

### Tips to Avoid Rejection
- ✅ Push notifications are implemented (native functionality)
- ✅ Haptic feedback on interactions
- ✅ Splash screen with proper branding
- ✅ Safe area support for notch
- ❗ You need a **Privacy Policy page** (can be a simple page on the website)
- ❗ Handle **Stripe payments on the web**, not in-app (avoids Apple's 30% cut + IAP requirement)
- ❗ Don't mention "web app" or "website" in the App Store listing

### In-App Purchases Note
Apple requires in-app purchases for digital content sold *within* the app. For Briefing Pro:
- **Recommended**: Handle subscriptions through the website (account page)
- **Alternative**: Use RevenueCat to manage Apple IAP + Stripe together
- The app can show a "Subscribe on web" link without violating guidelines (since 2024 anti-steering rules)

## Android Play Store Submission

### First-Time Setup
1. Log into [Google Play Console](https://play.google.com/console)
2. Create a new app, fill in the details

### Build
1. In Android Studio: **Build → Generate Signed Bundle / APK**
2. Choose **Android App Bundle (.aab)** (required for Play Store)
3. Create a signing key (save it securely — you need it for every update)
4. Upload the .aab to Play Console

### Required
- **App Icon**: 512x512 (already generated)
- **Feature Graphic**: 1024x500
- **Screenshots**: At least 2 for phone
- **Privacy Policy URL**
- **Content Rating**: Fill out the questionnaire

## Live Updates (Capgo)

After initial App Store approval, use Capgo for instant updates:

### Setup
```bash
npm install @capgo/capacitor-updater
npx cap sync
```

### Configure
Add to `capacitor.config.ts`:
```typescript
plugins: {
  CapacitorUpdater: {
    autoUpdate: true,
  },
}
```

### Deploy Updates
```bash
npx @capgo/cli upload --channel production
```

This pushes web code changes directly to users' phones — no App Store review needed.
Only submit a new native build when you add/change Capacitor plugins.

## Development Workflow

### Daily Development
1. Make changes to Next.js code as usual
2. Test in browser (`npm run dev`)
3. Changes auto-deploy to Vercel (web + mobile app)

### Testing on Device
```bash
# Quick sync + open
npm run mobile:ios    # or mobile:android
```

### When You Change Native Config
```bash
npx cap sync
# Then rebuild in Xcode/Android Studio
```
